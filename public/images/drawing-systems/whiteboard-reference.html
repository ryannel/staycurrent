A whiteboard shape vocabulary

Draw the blue additions in order. Name every object. The shapes are local shorthand; a label and a stated arrow meaning make the picture useful. Print with your browser’s Print command or the button below.

Keep one personality across the board

Spare omits detail. Soft rounds corners and adds a pale wash. Expressive keeps clear contours with a few small flourishes. The customer, site, API and database have the same meaning in all three.

Five minutes of practice

For this exercise, add a separate email queue. A customer uses a booking site. The site submits a repair to the Repair API. The API stores the request in Repair DB and enqueues a confirmation in Email jobs. An Email worker takes jobs and asks an external Mail provider to send them. Enclose the API, database, queue and worker in “Repair team”.

Spend one minute on names and space, two on shapes and relationships, one reading every arrow aloud, and one removing distracting detail. Use graphite for structure. Add blue only to the relationship being discussed.

Discussed solution

Customer → Booking site: uses. Booking site → Repair API: submits repair. Repair API → Repair DB: stores request. Repair API → Email jobs: enqueues confirmation. Email worker → Email jobs: takes job. Email worker → Mail provider: requests email delivery. The arrow from worker to queue means “uses”, not the direction in which a job travels. A data-flow view would draw Email jobs → Email worker and label it “confirmation job”.

The Repair team boundary contains four named elements. Mail provider is outside it. This sketch does not say that storing the request and enqueuing the job succeed atomically, nor that an email is delivered once. Put those questions beside the picture if they matter.

Keep: names, endpoints, arrowheads, relationship verbs, scope label. Optional: browser dots, file text lines, database seam, character hair, colour and tiny hatching. A named rectangle is always a useful fallback.
