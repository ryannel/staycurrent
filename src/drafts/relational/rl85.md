The application boundary turns a request into SQL and SQL results back into application values. It decides what is a value rather than SQL syntax, how many commands one response sends, which connection owns a transaction and when a result is safe to consume.

An object-relational mapper can generate those commands, while a driver sends them and decodes their replies. Neither removes the boundary. A list handler that looks like one function call can issue one query per order. A result iterator can keep a connection occupied after its handler appears to have finished.

We will follow a small workshop order list for tenant `t4`, customer `42`. Python's standard SQLite driver gives a complete runnable binding and batching example. PostgreSQL supplies the server-side cursor and error examples; their semantics are labelled separately.

Run this page’s SQL in a [fresh disposable PostgreSQL database](/review/relational/evidence/relational-fixtures.md). The workshop identifiers recur, but each article supplies its own table shapes.

## Bind values separately from SQL structure

Suppose a request contains a tenant ID and an order ID. String concatenation would let the order ID's quotes and operators become SQL. A parameter binds it as one value instead.

```python
import sqlite3

con = sqlite3.connect(":memory:")
con.executescript("""
CREATE TABLE orders (
  tenant_id TEXT NOT NULL, order_id TEXT NOT NULL,
  customer_id INTEGER NOT NULL,
  PRIMARY KEY (tenant_id, order_id)
);
CREATE TABLE lines (
  tenant_id TEXT NOT NULL, order_id TEXT NOT NULL,
  line_no INTEGER NOT NULL, description TEXT NOT NULL,
  PRIMARY KEY (tenant_id, order_id, line_no)
);
INSERT INTO orders VALUES ('t4','o81',42),('t4','o82',42);
INSERT INTO lines VALUES
 ('t4','o81',1,'Workshop seat'),('t4','o81',2,'Workbook');
""")
malicious_id = "o81' OR 1=1 --"
rows = con.execute(
    "SELECT order_id FROM orders WHERE tenant_id = ? AND order_id = ?",
    ("t4", malicious_id),
).fetchall()
print(rows)
```

```text
[]
```

The suspicious text is an ID that does not exist. It cannot close the string literal because it was never part of the SQL text. PostgreSQL drivers commonly use `$1`-style server parameters; Python SQLite uses `?`. Follow the driver API rather than adding quotation marks around placeholders yourself.

Parameters normally stand for values, not table names, column names or sort directions. Map a requested sort option to a fixed allowlist such as `newest → placed_at DESC, order_id DESC`. If dynamic identifiers are unavoidable, use the driver's identifier-quoting facility and an authorisation check for the named object. Escaping a string as a value does not make it a valid identifier.

A bound tenant is still untrusted if the caller can choose another tenant. Derive it from authenticated context and enforce access. Parameter binding prevents a syntax change; it does not grant permission to the requested record. [Constraints and tenant boundaries](/review/relational/rl79/) separates structural ownership from access control.

## Decoded values need a contract too

SQL types do not map perfectly to every language. JavaScript numbers cannot represent every 64-bit integer exactly; some PostgreSQL drivers therefore return large integers or exact decimals as strings. Converting them immediately with `Number()` can discard the precision the database preserved.

Choose whether the application uses an exact decimal library, integer minor units or a validated string representation. Preserve currency and units with the value. For dates and timestamps, check zone conversion, precision and whether a date-only value has accidentally become midnight in a device's local zone. Check SQL NULL distinctly from empty string, false and zero.

Python SQLite in the example returns tuples containing native values. Its default conversion does not turn a declared decimal column into a universal exact-money type. That choice belongs to the schema and adapter together. [Values, missing data and equality](/review/relational/rl78/) works through the database side.

Error replies also carry structure. PostgreSQL SQLSTATE `23505` identifies a unique violation and `23503` a foreign-key violation; inspect the code and relevant constraint identity rather than matching translated message text. SQLite's Python exceptions expose SQLite result codes. Log enough request context to diagnose the failure without logging secrets or full sensitive parameter values.

## Count the SQL behind the response

A lazy-loading ORM might generate this illustrative trace for two orders:

```sql
SELECT order_id FROM orders WHERE tenant_id = 't4' AND customer_id = 42;
SELECT line_no, description FROM lines WHERE tenant_id = 't4' AND order_id = 'o81';
SELECT line_no, description FROM lines WHERE tenant_id = 't4' AND order_id = 'o82';
```

That is one parent query plus one query per parent: N+1. For a bounded list of twenty orders, it becomes twenty-one commands. Five milliseconds of sequential exchange overhead per child would add 100 milliseconds before useful execution; that is arithmetic for an assumed delay, not a measured claim about this driver.

A request trace should count calls, returned rows and bytes, as well as the slowest command. Generated SQL is the evidence. An ORM option named “eager loading” may produce one join or several queries; inspect the statements and resulting cardinality.

Batch the selected children's IDs while preserving empty parents:

```python
parents = con.execute(
    "SELECT order_id FROM orders WHERE tenant_id = ? AND customer_id = ? "
    "ORDER BY order_id LIMIT 20", ("t4", 42)
).fetchall()
by_order = {order_id: [] for (order_id,) in parents}
if by_order:
    placeholders = ",".join("?" for _ in by_order)
    children = con.execute(
        "SELECT order_id, line_no, description FROM lines "
        f"WHERE tenant_id = ? AND order_id IN ({placeholders}) "
        "ORDER BY order_id, line_no", ("t4", *by_order)
    ).fetchall()
    for order_id, line_no, description in children:
        by_order[order_id].append((line_no, description))
print(by_order)
```

```text
{'o81': [(1, 'Workshop seat'), (2, 'Workbook')], 'o82': []}
```

The generated placeholder list contains syntax selected by the program from the number of authorised parents; its values remain bound. An empty parent list skips the child command. The response keeps `o82` and the parent ordering. A production batch also respects the engine's parameter limit and response-size budget.

Joining everything into one query is another choice, but two independently repeating child collections multiply each other. [Joins and the meaning of a result row](/review/relational/rl81/) shows two lines and two payments turning into four pairs. Query count is not the only cost: one huge join can transfer more rows and bytes than two bounded batches.

## One connection owns one transaction

A transaction is a sequence on one database connection. A pool convenience method may choose a connection independently for each call; it cannot safely stand in for an explicitly acquired connection across `BEGIN`, statements and `COMMIT`.

Use the driver's documented cleanup pattern. In Python SQLite, a connection context commits an open transaction on success and rolls it back on an exception, but does not itself close the connection. In a PostgreSQL pool, release the acquired client in a `finally` path; after a statement error, roll back the failed transaction before reuse. If rollback or connection health is uncertain, discard the connection under the driver's API.

Keep unrelated network work outside this interval where possible. Waiting for an email provider while holding a transaction can retain locks and a scarce connection for the provider's entire outage. [Outboxes and database-backed jobs](/review/relational/rl94/) gives that external effect a durable handoff.

Several reads on one connection do not automatically mean one view of time. PostgreSQL Read Committed ordinary statements can see different snapshots. A document assembled from several queries may need Repeatable Read, while a live list may accept newer children. Define that response contract before changing the query shape.

## A result can outlive the transaction that produced it

A fully buffered result can be consumed after the connection is released because the rows are already in application memory. A streaming result may still need the connection, cursor and transaction. Returning an iterator from a helper that immediately closes those resources gives the caller a result it cannot finish reading.

PostgreSQL makes the lifetime visible:

```sql
CREATE TEMP TABLE orders (tenant_id text, order_id text);
INSERT INTO orders VALUES ('t4','o81'),('t4','o82');
BEGIN;
DECLARE order_rows NO SCROLL CURSOR FOR
  SELECT order_id FROM orders WHERE tenant_id = 't4' ORDER BY order_id;
FETCH FORWARD 1 FROM order_rows;
COMMIT;
FETCH FORWARD 1 FROM order_rows;
```

The first fetch returns `o81`. The final fetch fails with SQLSTATE `34000`: the cursor no longer exists. A cursor declared `WITH HOLD` has a different lifetime and materialisation costs; it is not a general fix for hidden ownership.

Let the consumer's scope own the stream, or pass a callback that consumes it before cleanup. Close the cursor when the client stops reading, and bound the lifetime. A slow HTTP receiver can otherwise retain a snapshot, connection and old database versions. [Pagination and consistent exports](/review/relational/rl83/) distinguishes a live page from an export that needs one snapshot.

## A timeout does not settle the write outcome

A deadline can expire while waiting for a pool slot, executing a statement, reading results or receiving the commit reply. These are different states. Cancelling execution requires a protocol the driver actually supports, and a cancellation race still needs the final database response or a discarded connection.

For PostgreSQL, a statement error inside an explicit transaction leaves that transaction failed until rollback. A lost connection during commit is more awkward: the server may have committed before the reply was lost. The handler cannot infer rollback from its own timeout. Replaying an increment could apply it twice.

Use stable request identity `r81` and a transactionally recorded result when the operation needs replay safety. [Retries when a commit reply is missing](/review/relational/rl93/) develops the complete protocol. [Connections, overload and capacity](/review/relational/rl102/) owns pool sizing, queue bounds and overload decisions. Here the application's obligation is to preserve enough state to know what it can conclude, and to end resource ownership on every path.
