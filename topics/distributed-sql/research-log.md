# Distributed SQL: Spanner and CockroachDB — Research Log

## 2026-09-29 — cut v1

Founding run. The piece began as a CockroachDB deep dive and was widened the same day, on the operator's instruction, into the family piece with Spanner at equal depth.

CockroachDB: the cockroachlabs.com domain is blocked by this environment's proxy, so every documentation page was read from the source of the docs site in the `cockroachdb/docs` GitHub repository (the v26.2 tree and its includes), the cluster-setting defaults from the generated `settings.html` on the `release-26.2` branch of `cockroachdb/cockroach`, and release dates from the docs repository's `releases.yml`. Examined: the five architecture-layer pages, the life-of-a-transaction walkthrough, the transaction retry error reference, the read committed page, follower reads, hash-sharded indexes, the hotspots guide, replication zones, the multi-region pages, recommended production settings, common issues to monitor, monitoring and alerting, backups and restore, physical cluster replication, the upgrade includes, changefeed pages, the index type pages, the licensing FAQ include, the v26.2.0 release notes include, and the Cloud planning and cost pages.

Spanner: docs.cloud.google.com is blocked, but cloud.google.com itself is reachable, so the pricing page, the SLA page, the product page, and the Google Cloud blog were fetched directly (the editions announcement, Spanner Omni, the columnar engine preview, Spanner Graph algorithms, the multi-model post, the CQL endpoint post, and the September 2026 mutation-limit change). The OSDI 2012 paper was read in full from a GitHub mirror. The Spanner API protos in `googleapis/googleapis` supplied the isolation levels, read staleness modes, replica types, quorum types, edition and dialect enums, version retention default, backup schedules, change stream records, Data Boost and commit-delay options. The PGAdapter README came from `GoogleCloudPlatform/pgadapter`.

YugabyteDB facts come from the docs source in `yugabyte/yugabyte-db`; TiDB facts from `pingcap/docs` and the TiKV and TiDB licence files.

Confirmed only from indexed content or general knowledge, because the pages could not be fetched: the Spanner documentation pages on TrueTime, life of reads and writes, isolation levels, compute capacity (the storage-per-node figure), CPU utilisation targets (65% regional, 45% multi-region), schema design (UUID and bit-reversed sequence advice), secondary indexes (`STORING`, `NULL_FILTERED`), point-in-time recovery (the 7-day maximum), change streams, and quotas; the 2017 SIGMOD paper; the Aurora DSQL quotas, GA date, pricing, and foreign-key announcement; the CockroachDB Cloud per-vCPU rates; and the interleaved-table removal in CockroachDB v21.2. The web search budget was exhausted during the run, which limited third-party confirmation. All are flagged in the provenance.

An editorial and accuracy pass was applied before publication. It re-checked about forty figures against the cached docs sources, the Spanner protos, the paper, and the pricing page, confirmed the Spanner CPU targets, the 7-day retention maximum, the 10 TiB-per-node storage ceiling, the TiDB 256 MiB Region default, and the Aurora DSQL transaction limits and 26 August 2026 foreign-key date from indexed search results, corrected the 3-and-2 partition interview answer (every range keeps a majority on one side; none loses it), cut the piece from 9,700 to about 8,500 words by removing the Performance envelope's duplicates, merging the two hotspot questions and dropping the index-cost question, running Architecture as prose, and adding the hub and sibling links.

No lab measurements were run for this version. Every figure quoted is a vendor's documented default, limit, price, SLA, or the 2012 paper's measurement.
