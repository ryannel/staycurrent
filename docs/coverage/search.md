# Search and vector retrieval: proposed coverage map

18 October 2026. Proposal for discussion within the [field plan](../databases-and-storage-plan.md),
before independent planning review or writing. Use the [shared map conventions](databases-and-storage.md#map-conventions).

An expert user can define useful results, choose representations and retrieval
methods, preserve eligibility and freshness, measure retrieval errors and operate
the index. Lexical and vector methods share a collection because the application
often combines their candidates; they do not share an error model.

Running example: product P7, the catalogue's “blue mug” query, and versioned repair
manual passages such as R17/r7/model-A. Keep relevance judgements separate from
synthetic geometry. Small exact vectors explain distance, not real-model quality.
Base: `/learn/databases/search/`; retain the existing entrance.

The general vector lesson has one home at S05/S06/S08. S3 and PostgreSQL pages
retain the brief context a direct entrant needs, then develop actual API/index
behaviour. This avoids three competing tutorials on four invented vectors.
No new standalone playground is presumed; native execution matters when proving
filtered approximate behaviour or update visibility.
