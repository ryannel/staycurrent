## Running model

The figures share one PostgreSQL server and one update. The `products` table has rows P3 at 18.00, P9 at 9.50 and P7 at 20.00, all on page 12. Transaction 812 sets P7 to 22.00. The prices, the page number, the transaction id and the LSNs are invented and labelled as such in the intro.

The server figures have two lanes:

- **Memory** holds shared buffers (page 12) and WAL buffers. It is lost in a crash.
- **Disk** holds the table file (page 12) and the WAL file in `pg_wal`. It survives.

The application sits above both lanes. Rows and records fly in from where they came from. Figures 5, 6, 7 and 11 use this exact layout. The others zoom in on one part of it: the page, the buffer pool, the WAL stream or the flush path.

## Animations

Every figure has a label ("Figure N"), a title naming what it shows, narration inside the board, and a control bar below it: Play/Pause, Back, Next, a scrubber, Reset and a step count, with any parameter at the head of the bar. Each frame holds for at least 900 ms plus 45 ms a character of narration; repeated short frames (rows filling a page, records joining the WAL) run quickly. A figure plays once when half of it scrolls into view, pauses when it leaves, and rests on its last frame with reduced motion. On phones the control bar sticks to the bottom of the screen.

## Unsure about

- **TOAST.** One sentence remains: values wider than about 2 kB are compressed or moved to a TOAST table.
- **7,200 rpm.** The page shows the arithmetic: 7,200 rpm is 120 turns a second. The one-flush-per-turn ceiling is a standard estimate, not a PostgreSQL doc claim.
- **Power-loss protection.** The docs cover battery-backed controller caches and turning off a drive's write cache. The clause on drives that carry stored energy is general hardware knowledge with no cited source.
- **WAL timing.** Figures 6 and 7 keep the update record in memory until COMMIT. The captions say the WAL writer or another flush may write it sooner.
- **Simplifications in the figures.** Checkpoints happen instantly instead of spread over checkpoint_completion_target. Pages hold six row slots in the vacuum figure. The buffer model has no index pages. The checkpoint figure tracks pages 10 to 15 rather than only P7, so it can count page writes.
- **Torn pages.** The torn-page figure writes sectors in order. Real drives give no ordering guarantee, so the tear could be anywhere.
