#  is not attributable to the flush.)
# Reading: a plain (SYNC) FLUSHALL makes only its caller wait; other clients carry on. Inside MULTI, every client waits.
# Source check, redis 8.10.3 src/db.c flushCommandCommon(): "in case of SYNC, check if we can optimize and run it in bg as
#   blocking ASYNC" unless the client has CLIENT_AVOID_BLOCKING_ASYNC_FLUSH, defined in server.h as
#   (CLIENT_DENY_BLOCKING|CLIENT_MULTI|CLIENT_LUA_DEBUG|CLIENT_LUA_DEBUG_SYNC|CLIENT_MODULE). The variable blocking_async
#   is absent from 7.2.0's db.c and present from 7.4.0. Valkey 9.0.0's flushallCommand() has no such path: a SYNC flush
#   runs on the main thread, but Valkey's default lazyfree-lazy-user-flush is yes, so a plain FLUSHALL is ASYNC there.
