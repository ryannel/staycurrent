## Part 1: hash-field expiry, HSETEX, HSET, HINCRBY, expired_subkeys
  | R="redis-cli -p 7153"
  | x(){ echo "\$ redis-cli $*"; $R "$@"; }
  | echo "## HSETEX: does it discard other TTLs? (Redis 8.10.3, port 7153)"
  | x FLUSHALL
  | x HSET p name shoe description d price 4900 stock 17
  | x EXPIRE p 3600
  | x HEXPIRE p 100 FIELDS 1 price
  | x HEXPIRE p 200 FIELDS 1 stock
  | echo "# HSETEX with EX on stock only"
  | x HSETEX p EX 5 FIELDS 1 stock 16
  | x TTL p
  | x HTTL p FIELDS 4 name description price stock
  | echo "# HSETEX with no expiry option on stock (field had TTL 5)"
  | x HSETEX p FIELDS 1 stock 15
  | x TTL p
  | x HTTL p FIELDS 4 name description price stock
  | echo "# HSETEX KEEPTTL on price (field had TTL 100)"
  | x HSETEX p KEEPTTL FIELDS 1 price 4800
  | x HTTL p FIELDS 2 price stock
  | echo "# HSETEX no option on price: clears that field's TTL only"
  | x HSETEX p FIELDS 1 price 4700
  | x HTTL p FIELDS 2 price stock
  | x TTL p
  | echo "# Contrast: SET on an existing key with a TTL discards the key TTL"
  | x SET s v EX 100
  | x SET s v2
  | x TTL s
  | echo "## HSET clears field TTL; HINCRBY keeps it"
  | x DEL h
  | x HSET h a 1 b 2
  | x HEXPIRE h 100 FIELDS 2 a b
  | x HSET h a 5
  | x HINCRBY h b 1
  | x HTTL h FIELDS 2 a b
  | echo "## Last field expiry removes key; expired_subkeys vs expired_keys"
  | x CONFIG RESETSTAT
  | x HSET e f1 1 f2 2
  | x HPEXPIRE e 200 FIELDS 2 f1 f2
  | sleep 1
  | x EXISTS e
  | $R INFO stats | grep -E "^expired_(keys|subkeys)"

## Source check: redis/redis tag 8.10.3 src/t_hash.c hsetexCommand (lines ~4572-4700)
  For each named field: opt = HASH_SET_COPY | HASH_SET_NO_TEMPLATE_CONVERT; if (flags & (EX|PX|EXAT|PXAT|KEEPTTL)) opt |= HASH_SET_KEEP_TTL; hashTypeSet(db, o, field, value, opt);
  then hashTypeSetEx(o, field, expire_time) only when an expiry option was given. No call touches the key's own expiry or any unnamed field.
  => HSETEX with no EX/PX/EXAT/PXAT/KEEPTTL clears the TTL of the fields it names (like HSET). Key TTL and other fields untouched.
  hincrbyCommand (line 4788) and hincrbyfloatCommand (4852) call hashTypeSet with HASH_SET_KEEP_TTL => keep field TTL.
  Docs (redis/docs main, content/commands/hsetex.md): 'If the given key already holds a value, it is overwritten and any previous TTLs associated with the key are discarded.' Contradicted by source and observation; the wording matches SET's page.
  Docs content/commands/hexpire.md: 'Field expirations will only be cleared by commands that delete or overwrite the contents of the hash fields, including HDEL and HSET'.

## Part 4: DEL vs UNLINK vs DEL of a 20 MiB string (server-side SLOWLOG, microseconds)
  | R="redis-cli -p 7153"
  | x(){ echo "\$ redis-cli $*"; $R "$@"; }
  | x FLUSHALL
  | x CONFIG SET slowlog-log-slower-than 0
  | echo "# build two 1,000,000-field hashes with Lua"
  | x EVAL "for i=1,1000000 do redis.call('HSET', KEYS[1], 'f'..i, 'v') end return redis.call('HLEN', KEYS[1])" 1 bighash
  | x EVAL "for i=1,1000000 do redis.call('HSET', KEYS[1], 'f'..i, 'v') end return redis.call('HLEN', KEYS[1])" 1 bighash2
  | head -c 20971520 /dev/zero | tr '\0' v | $R -x SET blob >/dev/null
  | x SLOWLOG RESET
  | x DEL bighash
  | x UNLINK bighash2
  | x DEL blob
  | echo "# SLOWLOG: id, timestamp, microseconds, command"
  | $R SLOWLOG GET 5 | paste - - - - - - - - - - 2>/dev/null | head; $R SLOWLOG GET 5
  | x CONFIG SET slowlog-log-slower-than 10000
  SLOWLOG: DEL bighash (1,000,000 fields) 61002 us; UNLINK bighash2 6 us; DEL blob (20 MiB string) 1 us
