Indexes

An index helps a database find rows without searching the whole table. It stores values from selected columns in a structure that supports fast lookups. In PostgreSQL, it also stores references to the table rows those values came from.
  Consider finding one customer’s orders in a table containing orders for thousands of customers. Without a suitable index, the database may have to check every row to find the ones belonging to that customer. An index ordered by customer ID groups the customer’s entries together and points to their orders, even when those orders are scattered through the table. Once it finds the first matching entry, the database can read the following matching entries.
  The index’s arrangement determines what else it can do. An index on customer ID finds a customer’s orders, but it does not put them in date order. Adding the date to the index can also help a query return the newest orders first. These improvements have a cost: indexes take up storage, and the database must keep them up to date as orders are added or changed.
