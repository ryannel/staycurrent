Reading an execution plan
When you read a plan for your own query, start with the scans near the bottom. Check which rows they read and which they filter out, then follow those rows through the joins. A repeated index scan may look small until you multiply its average row count by loops. Compare estimates with actual counts at each operation, and look for sorts and aggregates that have to finish reading their input before they can return a row.
The plan gives you specific things to investigate: a filter that passes many more rows than expected, an index lookup repeated thousands of times, or a sort that spills to temporary files. Change one thing, run the query again, and compare both the plan and the result to check that the answer is still correct.
