The example query
To run the examples, open a SQL editor or psql connection to a new, empty PostgreSQL 18 practice database. Load the generated shop setup once, then keep that connection open for the statements below. This is a separate dataset from both the earlier receipt examples and the larger shop used in Indexes. The practice guide explains how to create a practice database.
The setup creates 10,000 orders shared equally among 1,000 customers. Every order has three lines: one unit of product 1, two of product 2, and three of product 3. Customer 42 owns orders 42, 1042, 2042, and so on through 9042: ten orders in all. With the same quantities on every order, we can work out the totals before running the query.

orders has an index on customer_id. The primary key of order_lines creates an index on (order_id, line_no), which can locate an order’s lines together. The database keeps these indexes up to date as the tables change. Indexes explains how they work and what they cost to maintain.
SELECT l.product_id, sum(l.quantity) AS units
FROM orders AS o
JOIN order_lines AS l ON l.order_id = o.order_id
WHERE o.customer_id = 42
GROUP BY l.product_id
ORDER BY units DESC, l.product_id;

The join returns the 30 lines belonging to customer 42’s ten orders. sum(l.quantity) adds the quantities for each product: ten lots of one, two and three give us totals of 10, 20 and 30. ORDER BY units DESC puts the largest total first, with product ID breaking any tie.

This SQL tells PostgreSQL which rows to match and which totals to calculate. PostgreSQL still has to decide which table to start with and how to find the matching rows.
