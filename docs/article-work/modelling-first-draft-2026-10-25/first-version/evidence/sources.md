# Technical sources — modelling first version

Checked 25 October 2026 using the web tool. This records research performed for the claims actually written, not an independent accuracy review.

- Silberschatz, Korth, Sudarshan, *Database System Concepts*, 7th edition, authors' chapter 6 slides: https://www.db-book.com/slides-dir/PDF-dir/ch6.pdf. Read design alternatives, relationship attributes and cardinality, non-binary relationships, reduction to relations, specialisation and total/partial, overlapping/disjoint subtypes. Supports the conceptual relationship vocabulary and the declared subtype choices. Original shop examples are applications, not reproduced textbook cases.
- Authors' chapter 7 slides: https://www.db-book.com/slides-dir/PDF-dir/ch7.pdf. Read functional-dependency/legal-state and candidate-key definitions; lossless split condition and unsafe split discussion; dependency preservation and 3NF/BCNF distinction; multivalued dependency example; atomic-domain/1NF discussion. Supports the concise definitions and formal boundaries. Article's keyed reconstruction, altered shop splits and offer tuples are original worked applications, checked in the owned model verifier where applicable.
- E. F. Codd, *Further Normalization of the Data Base Relational Model*, IBM RJ909 (1971), original report at https://apollo.inf.upol.cz/~urbanec/teaching/2021/data2/files/codd2.pdf. Search returned the report, but direct PDF fetch timed out. Read its reproduced primary text at https://thaumatorium.com/articles/the-papers-of-ef-the-coddfather-codd/1971b-further-normalization-of-the-data-base-relational-model/ through the functional dependency, candidate keys, full dependence/2NF and transitive dependence/3NF definitions. The transcription is unfinished later on; only the completed relevant sections were used. Original report's bibliographic identity also checked at https://www.sigmod.org/publications/dblp/db/labs/ibm/RJ909.html. No claim to having retrieved the full PDF. In particular 2NF checks every candidate key, including one not selected primary.
- Ronald Fagin, *Multivalued Dependencies and a New Normal Form for Relational Databases* (1977): https://research.ibm.com/publications/multivalued-dependencies-and-a-new-normal-form-for-relational-databases. Read the research publication's abstract; it introduces MVDs and 4NF stronger than BCNF and lossless decomposition. The textbook's detailed MVD treatment supplies the independence analysis. No claim of having read the full Fagin paper.
- PostgreSQL 18, Constraints: https://www.postgresql.org/docs/18/ddl-constraints.html, especially unique constraints, primary keys and foreign keys. Checked multi-column uniqueness, non-null references, matching existing targets and same-table references. The article describes their meaning and limits, not an observed failing statement or an engine experiment.
- PostgreSQL 18, Designing JSON Documents: https://www.postgresql.org/docs/18/datatype-json.html#JSON-DOC-DESIGN. Read the document-design section: relational columns and JSON can coexist; a predictable document structure remains useful. Article's boundary between descriptive documents and independently identified lines is an application of those principles and the foreign-key model.
- PostgreSQL 18, recursive query cycle detection: https://www.postgresql.org/docs/18/queries-with.html#QUERIES-WITH-CYCLE. Read cycle detection and traversal termination. Used only to distinguish terminating a traversal from preventing cyclic stored relationships; no query implementation taught.

EAV discussion is a structural assessment of the stated hypothetical triples, not a claim that all EAV implementations lack types or uniqueness. Dedicated columns' rules would have to be represented by EAV keys, metadata and checks. Historical price and total claims follow the centrally recorded meanings and exact arithmetic. No source establishes the shop's business policy; those assumptions are explicit illustrative choices accepted in the delivery context.

No runnable SQL/download or observed database protection is promised, so no database server was created. The focused model verifier uses integer cents and finite-set pair projections, recording actual local execution separately in model-checks.json. The proof rationale for the keyed split rests on the declared key over allowed states, rather than treating the sample run as a general proof.
