# Designing your data

Expanded 14 October 2026 in the existing `modelling.astro` route.

The reader is an engineer who knows what relational tables are and now wants to
design them. The main article needs to teach the whole decision: identifying
records, deriving healthy tables, choosing representations, retaining history,
enforcing rules and deciding when descriptive JSON or separate rows help.
Constraints and Tables and JSON remain useful deeper children, not prerequisite
repairs for missing main-article explanation.

Preserve the existing normalization derivation, typography, illustrated table
transformations, schema map, historical-price experiment, type comparisons and
receipt exercise. Their connected shop example establishes the facts reused by
the added constraint and representation sections. The new rule experiment asks
readers to change both proposed data and schema rules: missing rules admit bad
records; an extra uniqueness rule can reject a legitimate purchase.

Read the authoring, style and research skills, the current writing/illustration
references, original modelling/constraints/JSON drafts, and Sam Who's Load
Balancing introduction as voice context. Keep original prose and the existing
register. Independent reading and rendered desktop/phone/theme inspection are
coordinated by the root agent.

tutorial. Their relevant boundaries are stated locally and have onward reading.
