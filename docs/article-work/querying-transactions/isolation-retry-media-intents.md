## IsolationSnapshotLab (`isolation-snapshot-lab`)

Switching level and replaying the same writer/read ordering should make the
view distinction visible: Read Committed returns 20 then 22, while Repeatable
Read returns 20 twice; current committed catalogue price is 22 in either case.
The first query establishes the Repeatable Read snapshot. The report writes
nothing and neither read asks for a lock. The controls advance meaningful events
rather than animate execution time. Root repaired an uncued-reader ambiguity by
making the separate writer transaction's commit visibly external to the report.

## IsolationWriteSkew (`isolation-write-skew`)

Two featured-display rows start enabled. A reads B's product flag but writes its
own; B does the converse. Each snapshot gives a valid reason to hide one product,
but both committed writes leave the display empty. The drawn fork and merge
show two decisions from one earlier view, not two overwrites of the same row.
The caption explains why neither serial ordering permits that combined result.

## RetryDeadlock (`retry-deadlock`)

The record labels carry each holder/waiter relationship. Two opposed dependency
arrows make a closed cycle: A waits on B's P8 and B waits on A's P7. The database
aborts one, with no promised victim or detection latency. Both changes of that
victim roll back, rather than retaining one of its stock reservations.

## RetryCommitReply (`retry-commit-reply`)

Two alternative database histories converge on the same application observation:
no commit reply. One kept the checkout; the other discarded its attempt. The
diagram should make an unknown outcome distinguishable from a known rollback,
and connect recovery to the original operation identity K14. It deliberately
does not make an external payment part of the local transaction.

## Acceptance and limits

All four aids include their own setup and semantic text. The experiment retains
server-rendered initial content and a useful JavaScript-off explanation; controls
appear only after initialization. Native inputs/buttons work by keyboard, and a
separate status announces each step. Static arrows and row values are not controls.
SketchSheet/SketchArrow and theme-aware paper tokens preserve the existing light
and dark visual language. Root owns final phone/desktop/theme browser acceptance
and independent uncued review. The model has no database connection; SQL execution
scope is recorded separately in the evidence notes.
