# Application caching: open visual exploration

28 October 2026. The user explicitly set aside the existing design language and asked subagents to brainstorm each figure, then develop delightful teaching designs. Scope remains the six figures on the introduction; broader collections wait for a style judgement.

Three designers each considered two alternatives for two figures. Their briefs are beside this note. The selected concepts are implemented as working article illustrations:

1. A card workshop: source facts become a product card; a saved copy makes the next request visibly easier.
2. Process rooms and a shared commons: containment makes private memory tangible, and an outside shelf requires network crossings.
3. An address sorter: incomplete labels merge two different questions, while shop prefixes separate them.
4. Physical price tags: the source tag changes, the detached copy stays old, and invalidation removes it.
5. A print workshop: four waiting callers can share one piece of source work, then each receive an answer.
6. A memory shelf: a large answer occupies literal space and displaces smaller useful answers. Optional size exploration shows the consequence immediately.

The preserved human reference passages supply the teaching standard, not a requirement to copy their controls or drawing style. Sequence diagrams exposes waiting and ownership; Indexes keeps the query fixed while changing the physical work; Storage makes the cost of rows occupy space. The new designs retain object identity, consequential motion and honest examples while exploring depth, material, lighting and more elaborate choreography.

Complexity belongs in the implementation. The default scene must teach without input. Optional controls change a useful question or repeat a meaningful event. Each figure needs a readable final state, text alternative, reduced-motion treatment, keyboard controls and a narrow-screen composition. Animation time is presentation time, not service latency. The cache remains a disposable copy and Redis remains one implementation among several.

The implementation and scoped checks are complete; see `review.md`. This record supersedes the earlier introduction visual trial. It does not invalidate unrelated collection reviews or native Redis experiments, and does not authorise publication. The user will judge the design direction before any broader rollout.
