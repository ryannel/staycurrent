## Finding

**Medium · P1 · “Testing a prepared-plan repair”, source line 197.** “In a disposable session or explicit transaction, SET LOCAL plan_cache_mode = force_custom_plan and force_generic_plan make that comparison controlled” gives a disposable session as an alternative to a transaction. A reader opening a disposable autocommit session and following this instruction gets a warning and leaves the setting unchanged; their supposedly forced comparison can still use automatic planning. PostgreSQL 18’s [SET documentation](https://www.postgresql.org/docs/18/sql-set.html) explicitly says that `SET LOCAL` outside a transaction block has no effect. Make the transaction requirement unambiguous, or distinguish session-scoped `SET` from transaction-scoped `SET LOCAL`. The native verifier already encloses these commands in `BEGIN`, so this is a bounded prose correction; no execution rerun is needed.
