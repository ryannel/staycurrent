Recorded before plans, example facts, author notes, execution receipts or quality verdicts. Read the illustration sequence (labels, captions, manual states and HOT alternatives), then the body. The browser's full accessibility tree initially exposed body text alongside figures; the deliberate reading order was figures first. Current integrated review route, desktop 1280×720 confirmed in the page.

- The figures alone establish a useful causal route: connection → backend → shared page; cache replacement changes a slot, not stored identity; TID ends at a line pointer; two snapshots return different values from the same page; index key matching precedes heap visibility; HOT preserves the original index target; durable commit, data-page writing and pruning differ. P7, 20.00/22.00 and (12,3) remain recognisable across that route.
- Figure 2's chosen sweep is unusually helpful: slot 2 is skipped for a pin, slot 3's usage becomes zero without immediate reuse, and clean slot 4 is replaced. This prevents a vague cache/LRU lesson. Figure 4 keeps writer status separate from reader values. Figure 6 makes a second unchanged P7 key visible in the non-HOT cases.
- Body reading supplies terms immediately before the figures and connects the consequences without a glossary detour. The important qualifications sit near their claims: tiny-table index route is illustrative, buffer read need not reach the drive, BEGIN alone does not establish the snapshot, ctid is not business identity, covering is insufficient for heap avoidance, fillfactor is not a guarantee.
- No substantive teaching/editorial problem found in the first reading. Headings name the actual mechanisms plainly. The short TOAST passage is a local extension of the page-size explanation; background jobs return to dirty replacement rather than becoming a separate operations guide.
- Possible optional visual polish: Figure 3 states that compaction can move bytes and update item 3, but shows one static layout without a changed offset/before-after. The TID/line-pointer relationship itself is visible, so this did not prevent understanding.
