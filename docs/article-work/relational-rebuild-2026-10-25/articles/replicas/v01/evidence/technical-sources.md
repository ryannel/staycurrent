# Technical source checks

Checked 25 October 2026 against external primary sources. This is a conceptual article: no native replication trace, synchronous wait measurement, flush-survival or failover test is claimed. SQL execution evidence is limited to the displayed UPDATE and unchanged shop facts in `sql-result.json`.

| Consequential claim | Primary source and checked detail |
| --- | --- |
| Physical copy starts from a base and follows WAL; different replication mechanisms exist | [PostgreSQL 18 comparison](https://www.postgresql.org/docs/18/different-replication-solutions.html), [standby operation](https://www.postgresql.org/docs/18/warm-standby.html): physical WAL shipping is distinct from selective logical replication. Article explicitly scopes the drawn full-copy ordered-log model. |
| Receipt, durable flush and replay differ | [Replication protocol](https://www.postgresql.org/docs/18/protocol-replication.html), standby status-update fields; [administration functions](https://www.postgresql.org/docs/18/functions-admin.html), receive/replay functions and insertion/write/flush distinctions. Receipt in the conceptual drawing is deliberately not presented as a native function name; `pg_last_wal_receive_lsn` includes sync-to-disk. |
| Replayed commit enables visibility to new snapshots; existing snapshots need not refresh | [Hot standby](https://www.postgresql.org/docs/18/hot-standby.html), user overview: replayed commit visible to new snapshots, snapshot timing depends on isolation. Figure U-before-C is an illustrative physical replay cut, not observed execution. |
| Local durability versus asynchronous remote replication; required acknowledgement can wait indefinitely | [Standby synchronous replication](https://www.postgresql.org/docs/18/warm-standby.html), sections26.2.8 and high-availability planning: selected required standbys/progress and unavailable acknowledgements. |
| PostgreSQL on/remote_apply/remote_write promises | [WAL settings](https://www.postgresql.org/docs/18/runtime-config-wal.html#GUC-SYNCHRONOUS-COMMIT): non-off local flush, remote durable flush, remote application, remote filesystem write. Article states synchronous standbys must be configured. |
| Read-your-writes, monotonic reads, eligible copies and unavailable outcome | [Terry et al. 1994 original paper, Cornell copy](https://www.cs.cornell.edu/courses/cs734/2000FA/cached%20papers/SessionGuaranteesPDIS_1.html), sections 3.1/3.2 and 4. Terminology and eligibility principle adapted to one ordered history; H:C schedule is the article's illustrative protocol. It is not the paper's general version-vector implementation. |
| Recent delay differs from backlog and catch-up prediction; idle lag may become null | [pg_stat_replication](https://www.postgresql.org/docs/18/monitoring-stats.html#MONITORING-PG-STAT-REPLICATION-VIEW), position fields and lag note. [Administration functions](https://www.postgresql.org/docs/18/functions-admin.html) defines last transaction replay timestamp as primary record generation time, not a current freshness proof. |
| Query work competes with replay and may conflict | [Hot standby](https://www.postgresql.org/docs/18/hot-standby.html), handling query conflicts: resource contention plus recovery conflicts/cancellation. No claim that ordinary primary row locks block ordinary standby reads. |
| Retention can fill storage; removing needed log may require archive/fresh copy | [Replication settings](https://www.postgresql.org/docs/18/runtime-config-replication.html), wal_keep_size/max_slot_wal_keep_size; [replication slots view](https://www.postgresql.org/docs/18/view-pg-replication-slots.html), restart_lsn/wal_status/lost; [standby operation](https://www.postgresql.org/docs/18/warm-standby.html), archive/stream restart. |
| Reachability/currentness does not confer write authority | [PostgreSQL failover](https://www.postgresql.org/docs/18/warm-standby-failover.html): former primary must be excluded to avoid two writers. Article links out before the procedure. |
| Numeric positions alone cannot qualify a restored/promoted history | [Timelines](https://www.postgresql.org/docs/18/continuous-archiving.html#BACKUP-TIMELINES), branches and timeline history; [replication protocol](https://www.postgresql.org/docs/18/protocol-replication.html), cluster system ID/timeline and streaming along timeline ancestry. |
