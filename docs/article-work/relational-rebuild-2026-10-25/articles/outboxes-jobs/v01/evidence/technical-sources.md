# Consequential claims and sources

Primary sources checked25October2026 using web reads:

- PostgreSQL18 SELECT locking clause: https://www.postgresql.org/docs/18/sql-select.html#SQL-FOR-UPDATE-SHARE . SKIP LOCKED skips row-lock conflicts, suitable for queue-like consumers, incomplete reporting, LIMIT and lock placement. Explicit locking https://www.postgresql.org/docs/18/explicit-locking.html for row-lock lifetime. UPDATE https://www.postgresql.org/docs/18/sql-update.html for conditional changes and returned rows. Article applies these mechanisms to a stated outbox protocol; native verifier extracts exact displayed SQL.
- PostgreSQL18 current datetime https://www.postgresql.org/docs/18/functions-datetime.html#FUNCTIONS-DATETIME-CURRENT . now() is transaction start; statement_timestamp is statement start; clock_timestamp changes during execution. Article uses database wall clock and lock-first completion/renewal. Wall-clock jumps are a stated timing limitation, not a hard-real-time safety promise.
- AWS Prescriptive Guidance transactional outbox https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html . Atomic intent with database change; duplicates and consumer idempotency. Article does not adopt the source's broad timestamp/order/exactly-once wording: ordering is separately specified and enforced at receiver.
- Stripe idempotent requests https://docs.stripe.com/api/idempotent_requests . Inspected APIv1 parameter comparison, saved result and pruning after at least24h; after prune reused key creates new request. Article specifically names APIv1 and makes no claim that a mail provider has that contract.
- Mike Burrows/Google, Chubby paper, sections2.1/2.4 https://research.google/pubs/the-chubby-lock-service-for-loosely-coupled-distributed-systems/ and actual PDF https://storage.googleapis.com/gweb-research2023-media/pubtools/4444.pdf . Resource checks acquisition count to reject lower/delayed operations. The article's fence is an explicit bounded model, with resource scope and equality limitation.
- Amazon Builders' Library https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/ . Timeouts do not prove no effect; retry amplification, capped backoff, jitter. No deployment-specific numeric advice borrowed.

Also consulted SQS visibility-timeout documentation https://docs.aws.amazon.com/AWSSimpleQueueService/latest/SQSDeveloperGuide/sqs-visibility-timeout.html for comparison of invisibility/expiry and reappearance; no SQS implementation or exact-once claim is made.
