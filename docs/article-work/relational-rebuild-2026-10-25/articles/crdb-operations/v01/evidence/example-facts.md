Runtime example is an explicitly bounded customer/order read/update slice, not a full checkout grant set. shop_runtime, shop_migrate and shop_support retain their shared task meanings. Local implementation adds non-login shop_rw group, shop_view_owner for selected-field support views, and isolated shop_bypass test role. Support retains tenant/customer IDs + names and tenant/order/customer IDs + status, excludes placed_at/payment base paths. Context is exactly application_name '10'/'20', empty baseline matches no row; deliberately caller controlled and unsuitable as proof of person authority. Tenants are application organisations, not CockroachDB virtual-cluster tenancy.

Customers/orders carry tenant_id, orders use composite FK to customers (tenant_id,customer_id). Forbidden order103→customer4 update fails association; visible valid Rowan row remains an access issue. All ordinary DML probes rollback and final stored records are verified. First run exposed CLI autocommit-before-DDL, so DDL counterexamples were NOT assumed rolled back; root supplies explicit restoration supplement. Do not generalise transactional DML observations to schema changes.
