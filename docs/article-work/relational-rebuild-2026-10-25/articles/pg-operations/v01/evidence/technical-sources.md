Ordinary SQL is checked by evidence/pglite-verifier.mjs against a new in-memory PGlite 0.5.8 instance, actual PostgreSQL 18.3 WASM. Its exact displayed listings and outputs are in pglite-results.json. It closes the instance in finally. It does not claim concurrent native behaviour.

Native concurrency, lock, cancellation, timeout and connection-library checks use evidence/native-verifier.mjs. Root provisioned and removed the owned PostgreSQL 18.6 fixture, ran the frozen source with explicit disposable configuration, and retained the execution/provenance/cleanup outputs. The verifier asserts database/user/data directory/version/system identifier on every client before mutation, uses owned schema sc_operations_verify, and limits statements, lock waits and evidence polling. No existing/default database or personal data was targeted. The passing execution is native-v2-execution.json (exit 0, source e57d3cbe0657ee720e76b6662c73bc7e09d0f861be6486a2b7ce0612b04ecc0d unchanged before/after), with native-results.json, native-v2-stdout.txt and native-v2-cleanup.txt. The first attempt stopped at CREATE SCHEMA because pg_ is reserved; it is preserved under attempt01 and establishes no scenario outcome. Before the successful rerun, backend_start was changed to text to preserve microsecond precision for exact identity matching.

The passing run observed native PostgreSQL 18.6 (Debian 18.6-1.pgdg13+2), aarch64 Linux; system identifier 7700781592337428529; database sc_pg_operations; data directory /var/lib/postgresql/18/docker. root-fixture.json records the official image digest and localhost-only port. node-postgres package metadata reports 8.23.1. Privileged diagnostic clients are a verification convenience, not a tested least-privilege deployment. The actual connection settings were 100/0/3, separate from Figure 4’s explicitly invented 100/2/3.

Native results were read in full. H was idle in transaction / ClientRead with granted AccessExclusiveLock; W was active / Lock/relation with ungranted AccessShareLock and blocker H. Pool counts were total 1, idle 0, waiting 1. Cancelling H returned true without releasing the dependency. Owner rollback gave W and then the queued borrower [103 pending, 101 paid]. Cancelling W produced 57014 and its next command 25P02; lock timeout produced 55P03 and 25P02; statement timeout without a lock wait produced 57014. Bounded H termination returned true, removed H’s locks and allowed the same history result. Two later history executions moved pg_stat_statements calls 4→6 under the same entry/reset boundary. The final three order rows were unchanged. These checks support the exact article observations; their subsecond whole-harness runtime is not a service timing result.

No capacity or performance claim is derived from a single run. No host storage delay/exhaustion, prepared-transaction resolution, production permission boundary, HTTP response, crash, power loss or reconnect storm is executed by this article’s verifier.
