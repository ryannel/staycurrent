Failover transfers service to a surviving database copy when the current primary is unavailable. For writes, it has two separate obligations: the former primary must no longer be able to act as a writer, and the replacement must hold the history the service promises to retain. A server answering a health check proves neither. Follow the shop’s separate price experiment from Replicas, lag and read routing. The primary changes P7’s catalogue price from 20.00 to 22.00 and confirms the commit. Replica A has the change and commit durably stored, but has not replayed them. Replica B is still before the change. Then the primary becomes unreachable. We will first separate a broken link from a stopped writer, then choose which surviving history to use. This is split brain: two competing write histories for what the application treats as one database. Each copy can enforce its own keys and checks while the service as a whole has no single answer about accepted work. Promoting A is not a way to discover whether the primary stopped. It creates the second writer if the first is still active. Waiting longer for a heartbeat can reduce false alarms, but the elapsed wait does not enforce exclusion. Fence the former primary Fencing prevents the former writer from continuing authoritative work. The replacement must not accept writes until the authority protocol establishes that exclusion. Sending a shutdown request is only an attempt; the handover needs evidence that the required stop or isolation has taken effect. In Figure 1, an independent power-control path confirms that the old machine is off, and restart controls prevent it returning as a primary. A controlled switchover can instead confirm a clean shutdown and keep every supervisor from starting it again as a writer. When the machine cannot be trusted to respond, use a tested fencing mechanism that does not depend on that machine cooperating. Leases and fencing tokens A leader lease grants authority for a bounded interval, renewed through a coordination service. The old primary must stop committing before a successor can use that authority. A paused or overloaded process may not run its demotion code in time. Lease timing, clock assumptions and an enforced stop therefore belong to one tested protocol. Patroni’s watchdog design illustrates why a separate reset mechanism may be needed when ordinary demotion fails. A fencing token carries a generation of authority to the resource receiving an operation. Suppose a hypothetical receiver durably remembers generation 8 for one resource. After accepting 8, it rejects a delayed request carrying 7, with the comparison and operation enforced together. Merely adding “8” to a request does nothing if the receiver ignores it. A token checked by one file service also does not stop an old database from committing to its own disk. Agreement about the leader, enforcement at each affected resource and preservation of committed history must fit together. Sharding and distributed SQL develops replica agreement; Outboxes and database-backed jobs applies receiver enforcement to workers.
