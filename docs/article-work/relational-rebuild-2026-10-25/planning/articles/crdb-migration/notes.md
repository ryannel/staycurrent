## Method and ownership

Use a bounded offline migration: reviewed DDL, client-side CSV `COPY`, a finite frozen source and full comparison. The copy may load several tables separately while the candidate remains inaccessible; only the accepted complete candidate receives application authority. This is useful for a small shop whose permitted pause accommodates export, load and acceptance. Measure the whole pause on representative data before choosing it for a real service.

Mention continuous migration only to explain when this method stops fitting. Its initial copy must join an ongoing change stream without a gap; final catch-up, schema/identity coverage and failback add obligations. Link to current MOLT documentation for that separate tooling work, without promising a universal supported source version or a zero-downtime outcome. ## Primary sources checked

Checked 26 October 2026. Sources establish documented behaviour; they do not establish the proposed native outcomes.

- [CockroachDB v26.2 PostgreSQL compatibility](https://docs.cockroachlabs.com/docs/v26.2/postgresql-compatibility): protocol support does not establish identical semantics; integer `/` produces decimal results, unlike PostgreSQL's integral division. Its rendered division example has an inconsistent displayed PostgreSQL result, so use the prose rule plus native evidence, not a copied output block. Choose an explicitly intended whole-number or fractional result rather than mechanically substituting an operator.
- [CockroachDB v26.2 INT](https://docs.cockroachlabs.com/docs/v26.2/int) and [PostgreSQL 18 numeric types](https://www.postgresql.org/docs/18/datatype-numeric.html): CockroachDB's default INT/INTEGER is 64-bit; PostgreSQL integer is 32-bit. Explicit target INT4 preserves the existing range where that is the contract. Record the session's `default_int_size` and inspect actual target definitions. This matters to driver decoding and to the later PostgreSQL return, even if every copied value initially fits.
- [CockroachDB v26.2 COPY](https://docs.cockroachlabs.com/docs/v26.2/copy) and [PostgreSQL 18 COPY](https://www.postgresql.org/docs/18/sql-copy.html): CSV and explicit column lists provide a small logical data-transfer route. STDIN/STDOUT use the client connection. CockroachDB documents admin-only COPY; the fixture loader's authority must remain distinct from the restricted runtime role. A logical data copy does not transfer roles, schema or service configuration.
- [PostgreSQL 18 transaction isolation](https://www.postgresql.org/docs/18/transaction-iso.html): Repeatable Read retains the snapshot established at the first relevant statement; Read Committed can observe different committed states across statements. A common export transaction provides the intended source view. Keeping writers closed also makes that view final.
- [CockroachDB migration overview](https://docs.cockroachlabs.com/docs/molt/migration-overview): distinguishes conversion, loading, validation, optional ongoing replication and failback. Its current support table lists older PostgreSQL source versions rather than PostgreSQL 18; do not commission an unverified MOLT-on-18 recipe here.
