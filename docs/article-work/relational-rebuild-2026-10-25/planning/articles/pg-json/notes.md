## Primary sources checked

Checked 25 October 2026, pinning PostgreSQL 18 documentation rather than assuming the unversioned manual or a future release. No PostgreSQL execution, timings, size comparison or plan observation was performed for this plan.

- [JSON Types, sections 8.14.1–5](https://www.postgresql.org/docs/18/datatype-json.html): JSONB preserves semantic values rather than the original text; duplicate object keys collapse. Whole-row locking applies to document edits. Containment respects nesting but ignores array order and duplicate multiplicity. Default GIN supports existence, containment and JSONPath operators; path_ops omits existence and has no entries for valueless structures. Whole-column and subexpression indexes serve different expressions. JSONPath indexes extract supported equality clauses; a range-only path is not thereby an efficient GIN range search. Subscript assignment can create missing ancestors and rejects incompatible intermediate values. These are documented behaviours, not measured performance rankings.
- [JSON Functions and Operators, section 9.16](https://www.postgresql.org/docs/18/functions-json.html): JSON versus text extraction, NULL on missing/mismatched structure, existence and containment, shallow `||`, path edits, SQL/JSON and JSON_TABLE. `jsonb_set` requires earlier path steps to exist. `@?`/`@@` suppress several structural/type errors; lax JSONPath can adapt structure. Use deliberate strictness for diagnostics. Conversion to a typed record can accept numeric strings and turn missing/JSON-null values into SQL NULL, so conversion alone is not a full contract. Use a compact set of operations around the example rather than a function catalogue.
- [Constraints, section 5.5](https://www.postgresql.org/docs/18/ddl-constraints.html): CHECK accepts true or unknown. Required JSON fields need an explicit presence/type/null policy; a guarded expression tested `IS TRUE` is one option. Avoid relying on Boolean evaluation order around a cast; use a safe conditional or validate before conversion. Row-local checks cannot substitute for cross-table references. If the writer supplies SQL, test malformed cases and record the exact rule, not merely successful inserts.
- [Arrays, section 8.15](https://www.postgresql.org/docs/18/arrays.html): typed arrays; declared dimensions and lengths are not enforced. Keep their introduction bounded to how a homogeneous value differs from independent related rows.
- [Composite Types, section 8.16](https://www.postgresql.org/docs/18/rowtypes.html): named fields have types; ordinary table constraints do not travel with a composite value outside that table. Mention that limit if comparing composites with constrained detail rows.
- [Transaction Isolation, section 13.2.1](https://www.postgresql.org/docs/18/transaction-iso.html): a waiting Read Committed updater can apply its operation to the committed newer row, rechecking its condition. A server-side path expression and a stale replacement literal therefore have different consequences. Do not turn this into a general claim that JSON patches solve concurrent decisions or that stronger isolation has identical outcomes.
