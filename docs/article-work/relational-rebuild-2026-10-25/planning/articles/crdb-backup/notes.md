## Primary sources checked, 26 October 2026

- [BACKUP, v25.4](https://docs.cockroachlabs.com/docs/v25.4/backup): consistent timestamp, native object scopes and INTO collection syntax. Do not copy obsolete BACKUP TO syntax. The served versioned page contains newer cross-version material, so verify options/defaults against the pinned native fixture rather than inferring defaults from the URL.
- [Full and incremental backups, v25.4](https://docs.cockroachlabs.com/docs/v25.4/take-full-and-incremental-backups): collection versus chain, dependent increments, and storage/retention context. No incremental-only restore should be implied.
- [Revision history and point-in-time restore, v25.4](https://www.cockroachlabs.com/docs/v25.4/take-backups-with-revision-history-and-restore-from-a-point-in-time): history is bounded by the revisions captured; an interior target requires covering revision history. A later history-enabled increment does not retroactively add history to every earlier interval.
- [SHOW BACKUP, v25.4](https://docs.cockroachlabs.com/docs/v25.4/show-backup): collection paths, scope, full/incremental rows, start/end metadata and file-presence checking. A full backup's NULL start_time must not be drawn as unbounded available revision history. `end_time` alone is not the beginning of that history.
- [RESTORE, v25.4](https://docs.cockroachlabs.com/docs/v25.4/restore): new database name, dependent objects, destination restrictions, restored ownership/privileges and object-state restoration. Table-level restore cannot select arbitrary rows. A point restore materialises the selected state, not the source's entire MVCC history.
- [Backup validation, v25.4](https://www.cockroachlabs.com/docs/v25.4/backup-validation): file presence, schema restoration, data/checksum reading without ingestion, and complete restoration establish different things. Only the final application checks establish this shop's recovery outcome.

These are documented claims, not observations from a fixture. Avoid borrowing current Cloud managed-backup behaviour for a self-managed SQL drill.
