## Primary-source checks

Checked during this planning run (26 October 2026); PostgreSQL 18 and Citus stable documentation labelled 13.0.1. These are documentation checks, not executed cluster observations.

- [PostgreSQL table partitioning](https://www.postgresql.org/docs/18/ddl-partitioning.html): native partitions route rows and permit pruning/lifecycle work; foreign tables can also be partitions. Hence distinguish the normal local layout from adding a foreign-access mechanism rather than claiming partitions can never be remote.
- [PostgreSQL postgres_fdw](https://www.postgresql.org/docs/18/postgres-fdw.html), transaction management and remote optimisation: remote transactions use Repeatable Read unless local Serializable; this is not a shared cross-server snapshot. Remote prepare for 2PC is unsupported. Eligible filters and same-server joins can execute remotely; EXPLAIN VERBOSE shows remote SQL. Avoid promising arbitrary cross-server join pushdown or all-or-nothing multi-owner commit from one local BEGIN.
- [PostgreSQL PREPARE TRANSACTION](https://www.postgresql.org/docs/18/sql-prepare-transaction.html): prepared state survives a session and retains locks; an external transaction manager owns the global decision/recovery. This is not an application loop over independent COMMITs.
- [Citus distribution-column guidance](https://docs.citusdata.com/en/stable/sharding/data_modeling.html): key choice controls grouping; compatible co-location keeps related equal-key work together. Hashing a common value leaves that value together.
- [Citus distributed DDL](https://docs.citusdata.com/en/stable/develop/reference_ddl.html): column-distributed unique/primary keys include the distribution column; supported distributed foreign keys have placement/key restrictions. Reference tables are replicated single shards, with coordinated modifications. Schema-based sharding also exists; a brief recognition can distinguish it from column-based examples without adding a second tutorial.
- [Citus query processing](https://docs.citusdata.com/en/stable/develop/reference_processing.html): distributed planning routes/fragments work and combines answers; local PostgreSQL planning still matters. Do not infer that every query uses one worker or that every join remains local.
- [Citus utility functions](https://docs.citusdata.com/en/stable/develop/api_udf.html), `citus_move_shard_placement` and rebalancing status: co-located shards move together; supported modes use blocking copy or logical replication. Starting a background rebalance does not prove completion.
- [Citus cluster management](https://docs.citusdata.com/en/stable/admin_guide/cluster_management.html): logical-copy movement has a brief protected metadata handover and replica-identity requirements. Read default strategy claims cautiously: this page and the utility reference include inconsistent descriptions of defaults. This plan therefore requires an explicit strategy and observed plan/status rather than naming a default.
- [Citus DML](https://docs.citusdata.com/en/stable/develop/reference_dml.html) and [configuration reference](https://docs.citusdata.com/en/stable/develop/api_guc.html): prose concerning `multi_shard_commit_protocol` differs in operation scope/defaults. Do not turn those lines into a blanket current commit guarantee. Check the selected release's supported operation, settings and failure behaviour before providing runnable distributed-write claims.
- [PostgreSQL logical decoding concepts](https://www.postgresql.org/docs/18/logicaldecoding-explanation.html): continuation belongs to a database history; exported-snapshot alignment and restart/deduplication requirements support the online-transfer qualification. Native setup and counters remain in the logical-replication article.
