## Primary-source checks

Checked PostgreSQL 18 documentation on 26 October 2026. These support scope and important qualifications; retain exact links in the writer's research record and reader sources where used.

- [Introduction](https://www.postgresql.org/docs/18/textsearch-intro.html): document unit, token/lexeme preparation and `@@` matching.
- [Text search types](https://www.postgresql.org/docs/18/datatype-textsearch.html): casting is not normalisation; vectors retain positions and labels; queries have Boolean, phrase and prefix operators.
- [Controlling text search](https://www.postgresql.org/docs/18/textsearch-controls.html): query constructors, phrase stop-word gaps, field weighting, local ranking and excerpts. `websearch_to_tsquery` tolerates its search syntax; it does not replace SQL parameter binding. `ts_rank_cd` needs positions. Built-in ranks do not use corpus-wide statistics or represent probabilities. `ts_headline` works on source text, can highlight words outside a full query restriction, and its output needs safe HTML handling.
- [Tables and indexes](https://www.postgresql.org/docs/18/textsearch-tables.html): explicitly configured expression indexes and matching query expressions; stored generated-vector alternative and its storage/computation trade.
- [Preferred index types](https://www.postgresql.org/docs/18/textsearch-indexes.html): GIN is the documented normal choice for text search; it retains lexemes without weight labels, so weighted queries require row rechecks. GiST signatures can admit false positives. Full comparison and implementation details stay with the parent.
- [Additional features](https://www.postgresql.org/docs/18/textsearch-features.html): concatenating vectors shifts right-hand positions and differs around trailing stop words; labels do not create hard field boundaries. `numnode` and `querytree` help explain empty or unindexable requests. A changed thesaurus requires reindexing, whereas query rewrite changes need not.
- [Testing and debugging](https://www.postgresql.org/docs/18/textsearch-debugging.html), [Dictionaries](https://www.postgresql.org/docs/18/textsearch-dictionaries.html) and [Configuration example](https://www.postgresql.org/docs/18/textsearch-configuration.html): inspect token types, chosen dictionaries and emitted lexemes; configuration is an explicit vocabulary/language decision. Detailed custom dictionary creation is supporting material rather than an inventory to teach in full.
- [Generated columns](https://www.postgresql.org/docs/18/ddl-generated-columns.html): explicitly use `STORED` for this design, since PostgreSQL 18 defaults to virtual. Stored generation occurs on row writes and can only depend on the current row with suitable expressions.
- [REINDEX](https://www.postgresql.org/docs/18/sql-reindex.html) and [ALTER TEXT SEARCH DICTIONARY](https://www.postgresql.org/docs/18/sql-altertsdictionary.html): an index rebuild derives from table data; dictionary-file changes can require explicit session reload. The conclusion that reindexing a stored tsvector cannot regenerate its source-text representation is a direct design inference from these contracts. Regenerate stored vectors first; verify the exact procedure with the eventual runtime owner.
- [pg_trgm](https://www.postgresql.org/docs/18/pgtrgm.html): supports string similarity and index-assisted pattern operations; can assist misspelling suggestions beside full-text search. Pattern utility depends on extractable trigrams, not merely on index existence.
- [Limitations](https://www.postgresql.org/docs/18/textsearch-limitations.html): very large documents have representation and positional limits. This is a boundary to mention if a large-document example is chosen, not a reason to burden the small catalogue explanation with every limit.
