## Prioritized editorial recommendations

### 1. Give further-depth pages a clearer reason to read after their main page

This is the main collection-level weakness. The individual explanations are often excellent, but the required route teaches the same scene twice. Modelling already supplies the CHECK/NULL experiment, NaN, optional uniqueness, delete actions, JSON object rule, capacity details table and update boundaries. Transactions already supplies the price snapshot, featured-products write skew with the identical figure, deadlock, whole retries and K14 claim/replay protocol. Child openings mostly restart these lessons.

Consequence: a reader who has followed the sequence must work through known material before finding the promised depth. This reduces curiosity even when every sentence is accurate. The strongest references sustain curiosity by letting each solved problem reveal a new one; here the new page often resets the solved problem.

Two legitimate repairs depend on the publication's intended entry paths. If main articles must remain independently comprehensive, keep that breadth and make the children explicit close investigations, with brief recaps and early new cases. If the full route is the primary experience, move some detailed implementation from mains into children. Do not blindly cut useful foundation from mains merely to eliminate repetition.

Concrete child opening directions:

- Constraints: “Two requests can both check that a catalogue code is free. The database still has to let only one claim it. We’ll follow that collision, then examine exactly what the other rules permit—including a missing quantity that passes a positive check.” This signals depth beyond schema design.
- Isolation: “A condition inside one UPDATE was enough to protect a stock count. What if the condition reads another row? We’ll use two display flags to see why a stable snapshot—and even a single conditional statement—can still allow the wrong combined result.” Keep the ordinary-read lab as prerequisite recap or first linked investigation.
- Conflicts: “After a lost commit reply, a new connection finds no order. Is it safe to start again? Not yet: the first transaction may still be finishing. We’ll build the claim and recovery branches that settle that case without reserving the stock twice.” This foregrounds the distinctive pending-claim lesson.

Recheck by reading each main ending into its child opening: can a reader state the new question before a screenful of recap?

### 2. Make runnable depth optional where it overtakes the design argument
