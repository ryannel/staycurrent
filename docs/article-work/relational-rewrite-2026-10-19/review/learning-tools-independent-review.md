# Independent learning-tools audit

19 October 2026. Reviewer: `audit_learning_tools`, independently commissioned with
no conversation history. This is a coordinator condensation of the returned
report. The reviewer read the reference Indexes page and relevant components,
RL81, RL90, RL91, RL96, RL97 and RL123, and the shared renderer. They also
inspected RL90 in the browser and operated its Next-state control. This was not
a complete factual audit or a rerun of native worksheets.

## Findings

The sampled drafts contain useful worked examples and native experiments, but
their page aids generally do less explanatory work than Indexes. Calling their
stepped reveals interactive learning models would overstate what they provide.

Indexes changes a represented mechanism: selectivity changes the matched records,
pages and access-method counts; composite key order changes examined entries,
fetched rows and sorting; choosing a key changes its descent route. The shared
draft renderer instead changes which authored state is visible. Previous, Next
and Reset supply pacing without deriving an alternative outcome.

- **RL81, joins:** the static two-lines/two-payments/four-pairs figure is useful.
  Its small size permits inspection without controls. An inline experiment could
  help with varying payment count or predicate placement, but its absence alone
  does not invalidate this page.
- **RL90, isolation:** the reveal hides facts that must be compared. In the
  rendered page, Next replaces both earlier reads with “A commits”; no persistent
  display retains B's calculation or the committed rows. A causal display could
  expose snapshot timing, guarded versus absolute updates and isolation policy.
  The two-connection native exercise is substantive but leaves that comparison
  to the reader to construct.
- **RL91, locks:** Figure 1 claims a continuous waiting span but draws prose
  tracks with arrows, without a common timeline. Keeping B visibly waiting until
  A commits or rolls back would save reconstruction. The two-node deadlock graph
  is already small enough to understand statically; it need not be interactive.
- **RL96, recovery:** the static intact/broken log-chain comparison is useful.
  Figure 2 reveals paragraphs for one fixed target. Choosing a target while
  retaining orders and external acceptance would expose rescued and discarded
  work. The native drill provides different, valuable evidence.
- **RL97, lag:** receipt, flush, apply and snapshot visibility are related states,
  shown separately by the reveal. The observed-results table offers the stronger
  comparison. Changing replay or snapshot timing could make the distinction
  visible while preserving the native pause/resume worksheet.
- **RL123, ranges:** the static primary/secondary ordering comparison is useful.
  The four responsibility paragraphs behind Figure 2 never locate a key, its
  interval, gateway, leaseholder and replicas together. Changing a key or split
  boundary could directly test that spatial explanation.

## Judgement

These findings support **repair required at collection level for the learning-tools
pass**. They do not show that every sampled article fails as prose or needs an
interactive tool. Existing ready-as-draft metadata is insufficient evidence that
the media meets the Indexes reference. Preserve useful static examples and native
work, then reassess what each aid helps a reader predict or compare.
